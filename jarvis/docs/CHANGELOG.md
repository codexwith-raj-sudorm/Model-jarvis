## Session 11 — Concurrency hardening
Two crash-class bugs fixed: (1) *JNI thread safety* — the llama.cpp bridge used unlocked global state, so tapping stop or switching models mid-generation could segfault; every entry point is now serialized behind a `std::mutex`, plus a cooperative `std::atomic` abort flag with a new `nativeStopGenerate()` (stop is instant and callable from the UI thread; load/unload set abort *before* locking so they never wait long; `nativeIsLoaded` reads a lock-free atomic so status checks never block behind a generation). Bonus: a full re-read of `llama_jni.cpp` revealed the `std::string pending` declaration had been lost to the earlier edit race (undeclared identifier — wouldn't have compiled); restored in the rewrite. (2) *Main-thread unblocking* — `SherpaSttEngine.stop()`/`SherpaTtsEngine.stop()` joined their worker threads on the caller (UI) thread for up to ~2 s → stutter/ANR; joins stripped: cleanup now happens on the workers' own threads (`finally` blocks), TTS engine release moved to a daemon thread, the STT mic-open got a 3×200 ms handoff-grace retry, and the wake service's `onDestroy` join was removed for the same reason. `ChatViewModel.stopGeneration()` now calls `engine.stopGenerate()` so the ■ button actually halts the native token loop instead of just cancelling the coroutine.

## Session 12 — Context overflow & UTF-8 hardening
(1) *Mini-RAG text truncation* — web tool results could reach several KB; stacked into history they overflowed the model context and `llama_tokenize` returned a negative count (graceful error, but a dead turn). Three-layer fix: a strict **1500-character clamp on every tool result** at the single point where results enter history (`Orchestrator.MAX_TOOL_RESULT_CHARS` — guards all current and future tools), a **whole-prompt character budget** (8000 chars; history is trimmed oldest-first, always preserving the last 2 turns; sized for Hindi/Hinglish which tokenize at ~2 chars/token on Qwen), and WebSearchTool portioning tuned (top 4 passages × 350 chars) so a normal result lands *under* the clamp instead of being mid-sentence truncated. (2) *UTF-8 stream safety* — the partial-rune buffer (hold bytes until the character completes) already existed from Phase 0; the real remaining gap was malformed input: a stray invalid byte (bad lead, orphaned continuation run, overlong C0/C1, F5+) would still reach `NewStringUTF` and abort the JVM, and the full-result return path had no validation at all. Added `sanitize_utf8()` (drops invalid bytes, stops at partial tails) — now *both* the streaming flush (refactored into one `flush_pending` lambda) and the final return pass through it.

## Session 15 — Code review pass (the reviewer's turn on the reconstruction)
Systematic self-review of the Session-14 reconstruction found and fixed six real defects. (1) **Model path mismatch (critical)**: the scripts adb-push to `/sdcard/Android/data/<pkg>/files/…` (external app-specific storage) but ModelManager/SherpaStt/SherpaTts/KwsWakeDriver all looked in internal `filesDir` — the app would never have found the downloaded models; all four now resolve via `getExternalFilesDir(null) ?: filesDir` (`ModelManager.baseDir`, one shared helper). (2) **Use-after-free windows (crash-class)**: stop()/shutdown() released sherpa native objects on daemon threads while the mic/synthesis worker could still be inside native decode()/write() — every release path now bounded-joins its worker first (`MicLoop.awaitStopped`, `SherpaSttEngine.worker.join(500)`, `SherpaTtsEngine.executor.awaitTermination(500ms)`); joins happen on release threads only, so the Session-11 no-UI-join rule is intact. (3) **Wake ANR**: `JarvisWakeService.startDriver()` ran ONNX init (ASR fallback ≈1–2 s) on the main thread — driver start/stop now run on daemon threads under a `driverLock` with a `wantListening` gate so a stop racing init is honored. (4) **MicLoop had no open retry** — added the same 3×200 ms handoff grace the STT engine has (wake→overlay handoff is exactly where contention lives). (5) **Threading hygiene**: `Orchestrator.template`/`voiceMode` are now `@Volatile` (written from IO, read from Main); the agent turn runs on `Dispatchers.Default` (prompt building hits SQLite — never on Main); `send()` got a CAS guard against double-sends. (6) Cosmetic: dead `WebFetcher.isOnline()` removed, Theme's pointless `isSystemInDarkTheme()` dropped, overlay preview uses `ChatLog.OVERLAY_PREVIEW_TURNS`. *Meta-lesson, again: the parallel same-file edit bug from Session 6 re-manifested during this very session — three parallel edits to WakeDrivers.kt lost one, and a three-edit batch to ChatScreen.kt silently dropped two; all subsequent edits were strictly sequential with per-edit grep verification. Convention #2 is now enforced by scar tissue in two separate sessions.*
